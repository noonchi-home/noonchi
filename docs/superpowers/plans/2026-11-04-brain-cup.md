# 상위 판단 에이전트(클로이드의 두뇌) 1단계: 컵 시나리오 Implementation Plan

**Goal:** 폰 화면을 보며 "컵으로 마시는 중 → 컵만 두고 자리 비움 → 컵 안 사진 요청 → 판단 모델 결정 → 행동 직전 재확인"을 코드 상태 기계로 돌린다. 1단계는 twin-home 안의 새 모듈과 오프라인 재생까지다.

**Architecture:** 판단 흐름은 결정론 코드(상태 기계)가 정한다. VLM은 사진 판정만 한다(구조화 JSON, `unknown` 허용). 판단 모델은 도구로 부른다. 박석준 PAM 계약(`ai/pam/contracts.py`)과 같은 모양 `decide(frames 5장, memory, tasks) → {observation, reasoning, task_index}`(−1 = 대기)이고, 지금은 MockDecision과 PAM 자리표시만 둔다. 상태 기계는 순수 함수처럼 동작한다: 관찰·시간을 받아 이벤트와 "판단 모델을 불러 달라" 같은 할 일(intent)을 낸다. 비동기 호출은 바깥 실행기가 맡는다.

**Tech Stack:** TypeScript(Node 22), zod, vitest, OpenAI Responses API(`fetchRetry`), 새 npm 의존성 없음.

**근거:** 이 대화의 사용자 결정, SSOT 6.1(VLM 1회·`visible` 먼저·모름), `docs/experiments/2026-11-01-*.md`(최근 2초 최대 5장, 단일 진행·최신 우선, 근거 나이 1.5~2초, FIFO 금지), `ai/pam/contracts.py`.

## 고정 규칙

- 새 파일만 만든다: `src/brain/*`, `tests/brain-*.test.ts`, `scripts/brain-replay.ts`, 이 계획서. `src/phone/*`·`src/server/*`·`web/*`는 위치 맞춤 작업이 고치는 중이라 손대지 않는다.
- 커밋·푸시하지 않는다. 실제 VLM 호출은 30회 이하.
- 근거 나이 = 지금 − 판정에 쓴 가장 최근 사진의 촬영 시각. `staleMs`(기본 3초)를 넘은 판정은 모두 모름으로 본다.
- "자리 비움"은 사람이 안 보이는 것만으로 정하지 않는다. 사용을 본 뒤, 컵이 보이고(`cup_visible = yes`) 사람이 없는(`person_present = no`) 새 판정이 `awayMs`(기본 5초) 동안 이어져야 한다. 컵이 안 보이거나 사람 여부가 모름이면 시계를 처음으로 되돌린다. 폰 자세·트윈으로 "식탁을 비추는가"를 보는 것은 위치 맞춤 뒤 2단계에서 더한다.
- 요청은 셋이 다 맞을 때만 낸다: 내용물 모름, 그 값이 결정을 바꿈(판단 모델 what-if, 시험할 수 없는 모델이면 바꾼다고 본다), 사용 중 아님.
- 사람이 다시 보이면(새 판정 `person_present = yes`) 어느 단계에서든 요청을 거두고 "사용 중"으로 돌아간다.
- 행동(작업 번호 ≥ 0) 전에는 새 근거로 다시 본다: **판단이 끝난 뒤 찍힌** 사진의 판정이고, 근거 나이 ≤ `staleMs`, 사람 없음, 컵 보임. 판단에 쓴 사진·컵 안 답 사진은 재확인 근거가 아니다. 없으면 새 판정을 기다린다.
- 늦게 온 결과는 버린다: 상태 기계에 세대 번호를 두고 사람 복귀·취소·새 흐름마다 올린다. 판단 요청·결과는 세대를 들고 다니고, 다르면 버린다. 요청 답은 **요청 뒤에 찍힌** 사진만 받는다.
- 판정의 모든 항목은 창의 마지막 사진 기준이다(프롬프트로 고정, 과거 사건 항목은 두지 않음). 그래서 근거 시각 = 마지막 사진 촬영 시각.
- 판정 공백은 자리 비움으로 세지 않는다: 연속한 새 판정 사이가 `staleMs`를 넘거나, 판정 실패·오래된 근거가 끼면 자리 비움 시계를 처음으로 되돌린다.
- PAM 입력은 별도 어댑터 계약이다: 사진 5장이 정확히 2초 간격(t−8…t), 각 자리에 ±0.5초 안의 실제 사진, 시각은 2초 격자의 명목 시각(실제 촬영 시각은 따로 기록). 지금 PAM은 좌우 카메라 두 장이라 한 카메라 버전이 나올 때까지 우리 쪽 검사는 출력·기억 스키마와 사진 수·순서·시간대·간격까지만 한다.

## 1단계 결과

- 테스트: `tests/brain-{perception,decision,machine,runner}.test.ts` 57개 통과, `npx tsc --noEmit` 통과. codex 리뷰 4회(계획 P1 1·P2 4, 코드 P1 1·P2 3, 재검토 P1 1·P2 1, 재검토 P1 1) 모두 반영, 마지막 "없음".
- 대본 재생(`npx tsx scripts/brain-replay.ts`, 호출 0회): 들고 있음 6.5초 → 자리 비움 확인 15.7초 → 요청 → 합성 답(빈 컵) 18.3초 → 판단(모의): 컵 치우기 → 재확인 통과·실행 제안 20.9초.
- 실제 VLM 재생(`--live`, gpt-5.4-mini): 두 번, 합계 28회·$0.0242. 두 번째(15회·$0.0129)는 들고 있음 3.3초 → 자리 비움 확인 17.2초 → 요청 → 합성 답 21.0초 → 실행 제안 24.1초. 판정 답은 근거 1.2~2.6초 뒤에 왔다(첫 호출 1.8~3.2초).
- 실제 재생에서 찾아 고친 것: ① 자리 비움 끊김을 근거 시각으로 재면 판정 지연(1.5~2.6초) 때문에 다음 답 전에 3초를 넘겨 시계가 계속 처음으로 돌아갔다 → 마지막 판정 도착 시각으로 잰다. ② VLM이 옆모습만 보고 "음료 있음"이라고 답하기도 했다 → 요청 생략과 요청 답은 확신(confirmed)만 받는다.
- 리뷰로 고친 것: 재확인·판단 중에 판단 근거보다 뒤에 찍힌 확신 내용물이 다르면(도착 시점과 무관) 세대를 올려 다시 판단, 사람 없음인데 들고 있음·마심이면 모순으로 보고 자리 비움 시계 초기화, 판단 사진(2초 격자 5장)이 모자라면 미뤄 두고 기한 안에서만 다시 시도, 다시 묻기도 호출 상한·비용에 셈.
- 합성인 것: 마지막 장면 12초 늘리기, 컵 안 답(실제 위에서 찍은 사진이 없음), 판단 모델(모의).

## 2단계 연결 목록(지금 하지 않음)

1. `src/server/start.ts`: `BRAIN=1`이면 실행기를 만들고 폰 프레임(`feed`)을 넣는다. 폰 프레임에 촬영 시각이 없으면 받은 시각을 쓰고 표시한다.
2. 이벤트: `{type:"brain"}` → 대시보드 추론 기록 칸, `{type:"request"}` → 폰 화면 위 큰 글씨(거둘 때 `active:false`).
3. 폰: 요청이 뜬 동안 📷를 누르면 그 사진을 "요청 답"으로 판정한다.
4. 위치 맞춤 뒤: "식탁을 비추는가"를 폰 자세·트윈으로 판정해 자리 비움 조건에 더한다.
5. PAM 한 카메라 버전이 나오면 `PamDecision`을 채운다(호출 형식·키는 박석준과 정함).
6. 행동 실행(트윈 가전·사람에게 부탁)과 결과 확인.
