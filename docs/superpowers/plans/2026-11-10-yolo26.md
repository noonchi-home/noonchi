# YOLO26n 감지기와 YOLO26n-pose 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**목표:** 관찰 흐름의 물체 감지기를 YOLOX-Tiny에서 YOLO26n으로 바꾸고, 사람이 보이는 프레임에 YOLO26n-pose를 더 돌려 World State에 사람 자세(서 있음·앉아 있음·누워 있음)와 손에 듦(컵 손에 있음·물건을 들고 있음)을 넣는다.

**구조:** 두 모델은 이 PC에서 내보낸 ONNX(ultralytics 8.4.x, opset 17, 입력 640)를 저장소 `models/`에 커밋한다. 감지 워커 하나가 JPEG를 한 번 풀고 640 레터박스 한 장으로 감지와 자세를 돌린다(자세는 사람 0.5 이상일 때만). 자세 규칙은 Perception-lab `lab/scene.py`·`scene2.py`를 옮긴 `src/world/pose.ts`이고, World State가 같은 프레임에서는 자세 사실을 VLM 답보다 앞에 둔다.

**기술:** onnxruntime-node 1.31(CPU, 워커 스레드), jpeg-js, Vitest.

**출처:** 사용자 결정 「지훈이가 만든 비전 모델로 바꾸자 두 개 다」·「두 개 다 트윈서버에 올려줄래?」. VLM 경로(모델·프롬프트·스키마)는 이번 범위 밖이다.

## Global Constraints

- 모델 파일: `yolo26n.onnx` sha256 `b164246692cd533f5d2ea16426c1e81da686ad64d07740f35ab762715faaf4c3`(입력 images [1,3,640,640], 출력 output0 [1,84,8400]), `yolo26n-pose.onnx` sha256 `dd0e47a03ea0f2b9e766b038559de14fb1dd5e51d8dfb331051740998628d91e`(출력 [1,56,8400]). 원본 가중치 `yolo26n.pt` `9b09cc8b…4fef`, `yolo26n-pose.pt` `eb3bb826…22a9`(Ultralytics GitHub 릴리스). 라이선스 AGPL-3.0.
- 내보내기는 같은 물체에 상자를 여럿 낸다(컵 상위 상자끼리 IoU 0.99). 그래서 NMS를 한다.
- 받는 기준은 그대로: 감지 최소 점수 0.25, World State 사람 0.5·물건 0.4.
- 저장소 하나: Perception-lab 경로를 쓰지 않고 규칙을 옮긴다. 출처는 `docs/provenance.md`.
- PAM에는 글만 간다. 자세·손에 듦은 World State 변화 글로만 나간다.
- 시험·빌드는 `npm run heavy -- <명령>`.
- git: 경로를 하나씩 add, `.gitignore`·`.ignore`·`graft/`는 건드리지 않는다. 커밋하고 push하지 않는다.
