# 클로이드의 눈 H.264 표시 영상 구현 계획

**Goal:** 시연 화면의 클로이드의 눈을 선명하게 보인다. 폰이 표시용 영상(H.264, 약 720p, 24–30fps)을 따로 보내고, 대시보드가 그 영상을 그린다. 분석용 JPEG 경로(YOLO·VLM)는 그대로 둔다.

**Architecture:** 폰은 WebCodecs `VideoEncoder`로 카메라 텍스처를 H.264(avc 형식, 키프레임 약 2초마다)로 인코딩해 지금 쓰는 `/phone/events` WebSocket에 바이너리 패킷(`video_config`·`video`)으로 보낸다. 서버는 판단하지 않고 중계만 한다(SSOT 2.2): 마지막 디코더 설정(description)과 마지막 키프레임부터의 묶음(GOP)을 캐시해 늦게 붙은 대시보드도 바로 그린다. 대시보드는 `GET /api/eye/video`(길이 붙인 메시지가 이어지는 HTTP 스트림)를 워커에서 읽어 `VideoDecoder`로 `<canvas id="eye-video">`(OffscreenCanvas로 넘김)에 그린다. H.264를 못 쓰거나 영상이 3초 넘게 안 오면 지금 MJPEG 화면을 보인다.

**Tech Stack:** Node 22 + TypeScript(tsx), ws, zod, vitest, 빌드 없는 ES 모듈, WebCodecs, 헤드리스 Chrome(CDP) 확인.

**Spec:** SSOT 2.2(판단은 서버 한곳, 중계는 판단 아님), 9.6(폰 AR), 12(클로이드의 눈은 표시 전용, 엔진 입력 아님).

## Global Constraints

- 분석 경로는 바꾸지 않는다: JPEG 프레임 패킷·`MAX_BUFFERED`(512KB) 드롭·`onFrame`·두뇌 입력 그대로.
- 표시 영상은 와이파이가 막히면 먼저 양보한다: 폰 쪽 영상 기준 `bufferedAmount` 256KB(분석 512KB보다 낮음). 넘치면 델타 프레임을 버리고 다음 프레임을 키프레임으로 다시 시작한다.
- 서버는 영상 내용을 보지 않는다. 마지막으로 설정을 보낸 폰 연결 하나의 영상만 받는다(두 폰이 섞이지 않게).
- 집을 바꾸면 눈 화면(EyeFeed)과 폰 서버가 새로 만들어진다. 폰은 새 연결에서 설정·키프레임을 다시 보내고, 대시보드는 끊긴 스트림을 다시 붙인다.
- 대시보드 DOM은 `#eye` 안에 `<canvas id="eye-video">` 하나만 더한다. CSS는 `web/style.css` 끝 짧은 블록 하나. 디코드는 새 파일 `web/eye-video.js`, `app.js`는 붙이는 몇 줄. 폰 인코더는 새 파일 `web/phone/display-encoder.js`, `phone.js`는 붙이는 몇 줄. glass 디자인 작업과 겹치지 않게 레이아웃·색은 손대지 않는다.
- 초점 고리(FOCUS=1, 기본 꺼짐)는 JPEG 화면에만 그린다. 영상에는 그리지 않는다.
- 커밋하지 않는다.

## 스트림 형식

- 폰 → 서버(바이너리 WS): 지금 패킷 그대로 `[헤더 길이 u32][JSON 헤더][본문]`.
  - `video_config`: `{kind, codec, width, height}`. 본문은 avcC description(비어 있을 수 있음).
  - `video`: `{kind, key, ts, width, height}`. 본문은 청크.
- 서버 → 대시보드(`GET /api/eye/video`, `application/octet-stream`): `[헤더 길이 u32][본문 길이 u32][JSON 헤더][본문]`가 이어진다.
  - `{type:"config", codec, width, height}` + description.
  - `{type:"chunk", key, ts}` + 청크.
  - 붙자마자 설정 → 캐시한 GOP(키프레임부터) → 실시간.

## 완료 조건

- 폰 페이지가 H.264를 쓸 수 있으면 대시보드 눈 칸이 canvas 영상으로 바뀌고, 못 쓰면 지금 MJPEG 그대로.
- 늦게 연 대시보드도 1초 안에 그림이 나온다(캐시한 GOP).
- 집을 바꾼 뒤 폰이 다시 붙으면 영상이 다시 나온다.
- `/api/eye/stats`에 `display: {codec, width, height, fps, kbps, key_age_ms, viewers}`.
- 서버 로그에 폰 연결·끊김 한 줄씩.

## 정한 것(헤드리스 확인으로)

- 폰 프레임은 기본으로 readPixels(RGBA)로 만든다. DOM 밖 WebGL canvas에서 바로 만든 프레임은 이 PC 크롬 하드웨어 인코더에서 10fps였다(readPixels 26fps, 소프트웨어 인코더 30fps). 폰에서 시험할 때만 `?vsrc=canvas`.
- 인코더가 2초 동안 절반 넘게 밀리면 canvas → readPixels → 소프트웨어 인코더 순서로 한 단계씩 바꾼다. 폰 ⋯ 메뉴에 지금 경로가 보인다.
- 대시보드 디코드는 워커에서 한다. 같은 출처 3D 트윈 iframe이 셰이더 컴파일로 메인 스레드를 몇 초(새 프로필에서는 30초 넘게)씩 막아 메인 스레드 디코더는 밀렸다.
- 헤드리스 한 바퀴(폰·대시보드 크롬 따로): 592×1280, 서버 중계 28–29fps, 대시보드가 그린 장 28/초, 늦게 연 대시보드 첫 그림 0.8–1.0초, 폰 영상이 끝나면 MJPEG로 0.1초 안에, 집 바꾸기 뒤 폰 영상 1.2초·대시보드 1.9초.
