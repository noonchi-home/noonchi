# 한양목련 디지털 트윈 전면 재구축 (사용자 원문 요약 없이 핵심 그대로)

## 1. 목표
한양목련(twin-studio home id `mokryeon_180b`) 평면도 기반 트윈을 고품질 Three.js 3D Isometric Dollhouse로 재구축한다.
1. 실제 평면도와 공간 구조를 정확히 유지하며 고품질 Isometric Dollhouse로 시각화
2. 집 전체 보기에서도 공간 구분이 명확하고, 방·가전을 선택하면 충분히 크게 볼 수 있음
3. CLOiD 에이전트가 집중하는 공간을 자동 확대하고 관찰·판단·계획·실행 상태를 3D에 반영
4. PBR 재질, 고품질 가구 모델, HDR 환경 조명, 부드러운 그림자, GTAO, SMAA로 건축 시각화 수준의 실시간 렌더링
최종 결과물: CLOiD의 실시간 상황 인식과 행동 계획을 시각화하는 인터랙티브 디지털 트윈.

## 2. 기존 분석·보존 원칙
코드 수정 전 분석: 프론트·Three.js 스택, 평면도·공간 데이터, 벽·문·창·바닥 생성 방식, 가구·가전 모델과 배치, 좌표계·크기·축척, CLOiD 위치·카메라 동기화, 에이전트 상태·판단·계획 데이터 구조, API·WebSocket·상태 관리·이벤트, 대시보드와 트윈 연결.
평면도 구조·실제 좌표·가전 식별자·에이전트 연동 계약은 가능한 한 유지. 기존 기능 손실 금지. 검증되지 않은 평면도·가구 배치를 임의 생성 금지. 데이터가 부족하면 실제 데이터와 시각적 임시 모델을 구분(임시 모델을 실제 배치처럼 취급 금지). 기존 구현을 무조건 재사용·폐기하지 말고 범위를 판단.

## 3. 시각 목표: High-quality Isometric Dollhouse
Isometric 3D Dollhouse, Architectural Cutaway, 고품질 실내 렌더링, Clean·Modern·Realistic, 실시간 상호작용. 30~50도 높은 각도 기본. 천장 제거, 방해되는 외벽은 절개·숨김(구조 파악할 만큼은 남김).
최우선: 집 전체가 화면 대부분 차지, 여백 최소, 공간 경계 명확, 가구·가전이 실제 형태에 가깝게, 작은 물체까지 형태·재질 구분, 밝고 자연스러운 건축 시각화 색감, 그림자는 쓰되 내부가 어둡지 않게, 과한 Bloom·반사·효과 배제. 화려함보다 공간 가독성과 사실감의 균형.

## 4. 렌더링
4.1 WebGLRenderer 우선(antialias, high-performance, DPR ≤2, SRGB, ACESFilmic, exposure 1.0, PCFSoftShadowMap) — 설치 버전 기준으로 검증·조정. 후처리에서 MSAA 미적용 시 별도 AA, 중복 낭비 금지. Canvas 크기·DPR·투영 행렬·후처리 타깃을 리사이즈에 동기화.
4.2 PBR: 벽 무광 페인트, 바닥 타일·목재, 가구 목재·패브릭·가죽, 가전 금속·플라스틱·유리, 창 반사·투명. MeshStandard/Physical. BaseColor·Roughness·Metalness·Normal·AO. UV·텍스처 없으면 절차적·타일링.
4.3 GLB/glTF 고품질 모델: 실제 축척, 원점·방향 통일, 중복 로딩 방지, 인스턴싱, Draco·Meshopt, KTX2, 폴리곤·텍스처 최적화. 우선순위: CLOiD와 상호작용하는 가전 > 주요 가구 > 소품. 고품질을 못 쓰면 단순 모델로 대체하되 실제 모델처럼 보고 금지.
4.4 조명: HDRI 환경광(배경 이미지가 아니라 재질 광원), PBR 반사, 방향성 주광, 창 방향 고려 실내광, 보조광, 접지 그림자. PMREM 확인.
4.5 Soft shadows: PCF, 해상도·범위 최적화, bias, acne·peter panning 최소화, 정적 물체는 정적·베이크 검토. 전체 렌더 시 과도한 성능 저하 금지.
4.6 AO: High는 GTAO 우선(벽·바닥·가구 접촉부, 좁은 틈, 수납장·가전 주변). 과하게 어둡지 않게. 저성능은 SSAO 또는 AO 끄기.
4.7 AA: 기본 SMAA(카메라가 계속 움직이므로). TAA는 선택적 고품질 정지 모드로 검토(이동 안정성, 상태 변화 잔상, 전환 후 누적 초기화, UI 선명도, GPU 비용). TAARenderPass에 reprojection이 있다고 가정 금지. SMAA·TAA 중복 금지, 비교 후 결정. 후처리 순서(특히 SMAA와 OutputPass 색공간·순서)는 설치 버전 공식 문서로 검증.
4.8 품질 프리셋 3개: High(높은 DPR, 고품질 텍스처·그림자, GTAO, SMAA, 고품질 환경광) / Balanced(적응형 DPR, 중간 그림자, 저해상 AO 또는 경량 대안, SMAA, 최적화 텍스처) / Performance(낮은 DPR, 최소 그림자, AO 끄기 가능, 가벼운 AA, 장식 LOD). 데스크톱 고품질 + 일반 노트북에서 원활.

## 5. 카메라
5.1 기본 OrthographicCamera: 비스듬히 내려다봄, 건물이 화면 최대, 건물 중심·실제 외곽 기준 정렬, 여백 최소, 회전 범위 제한, 바닥 아래 시점 금지. 확대는 zoom/투영 영역 조정(위치 이동만으로 확대된다고 가정 금지).
5.2 Fit to Selection: 실제 3D Bounds → 현재 카메라 방향으로 화면 투영 → 사용 가능 화면 영역 → zoom·target 조정 → 여백. Box3 중심만 쓰지 말고 카메라 방향·화면 비율 반영.
5.3 Smooth transition: 위치·target·zoom·회전 보간, ease-in-out, 전환 중 중복 명령 처리, 전환 중 대상 변경 시 새 목표로 자연스럽게. 사용자 조작과 충돌 금지.
5.4 Zoom to cursor.
5.5 Dynamic wall hiding: 카메라-대상 사이 벽 처리(표시·투명도), 최소 경계 유지, 선택 방 벽은 필요한 만큼만, 시점 변경 시 재계산, 투명 벽 깊이 정렬 문제 방지. 숨김 vs Cutaway 중 안정적인 쪽.

## 6. Semantic Zoom
L1 House Overview: 집 구조, 공간 구분, CLOiD 위치, 에이전트 집중 공간, 주요 이벤트 위치, 개략 경로. 상세 상태·긴 글 숨김.
L2 Room Focus: 그 공간 가구·가전, CLOiD 위치·방향, 관찰 대상, 행동 목표, 이동 경로, 가전 주요 상태, 판단 표시. 다른 공간은 맥락만.
L3 Object Focus: 선택 물체 강조, 이름·종류, 현재 상태, 가능한 행동, CLOiD와 공간 관계, 계획된 상호작용.
L4 Detailed Inspection: 상세 상태, 센서 데이터, 판단 근거, 계획 행동, 실행 결과, 관련 이벤트 기록.
수준은 선택 대상·모드·화면상 크기로 결정. 경계 히스테리시스.

## 7. Focus + Context
메인 트윈 최대 화면. 집중 모드에서 미니맵(집 윤곽, 공간 경계, 집중 공간, CLOiD 위치, 현재 카메라 영역; 메인과 같은 원본 데이터). 방 클릭→Room Focus, 가전 클릭→Object Focus, 빈 공간/전체 보기 버튼→Overview. 강조: Outline, 약한 emissive, 바닥 영역 강조, 주변 명도 감소, 경계선 중 적합한 것(과하지 않게).

## 8. CLOiD 에이전트 자동 집중(가장 중요)
8.1 이벤트에서 구분 수신: CLOiD 위치, 관찰 공간, 주요 관찰 대상, 현재 목표, 계획 대상 공간, 계획된 상호작용 대상, 실행 중 행동, 결과, 계획 수정·재판단. 실제 제공 필드를 확인하고 부족하면 View State Adapter 설계. 다 있다고 가정 금지.
8.2 자동 Room Focus: 에이전트가 중요하게 판단하는 대상 공간을 따라감(물리 위치만 따라가는 것 아님).
8.3 자동 Object Focus: 상호작용 결정 시 그 물체 강조, 주변과 CLOiD 관계, 실행 행동·상태. 극단 확대 금지.
8.4 계획 변경 시 전환: 최소 유지 시간, 같은 공간 중복 이동 방지, 짧은 시간 이벤트 병합, 높은 우선순위 선점, 오래된·역순 이벤트 무시, 이벤트 처리와 렌더 분리.
8.5 수동 우선: Auto Follow / Manual Explore / Return to Agent. 드래그·휠·터치 시작 시 수동 전환. 수동 탐색 중 화면을 강제로 바꾸지 않음.
8.6 자동 복귀: 다음 집중 대상이 있으면 이어서, 없으면 안정화 시간 뒤 Overview. 일시적 공백을 완료로 오인 금지.

## 9. 사고 과정·행동 계획 시각화
9.1 Observation: 카메라 위치·방향·대상·시야(실제 자세·FOV 있을 때만 정확한 시야).
9.2 Reasoning: 중요하다고 판단한 공간·물체 강조. 시스템이 제공하는 요약·구조화 근거만 사용(내부 사고 임의 생성 금지).
9.3 Planning: 시작점, 목표점, 계획 경로, 상호작용 가전, 순서, 현재 단계. 경로가 있으면 실제 경로, 목표만 있으면 경로처럼 그리지 않음.
9.4 Execution: 대기·실행 중·성공·실패·재계획, 예정과 실제 결과 구분.
9.5 Replanning: 기존·변경 목표, 기존·새 경로, 사유 요약(있을 때), 현재 실행 상태. 색·선 스타일 구분.

## 10. 데이터·좌표계
평면도 좌표, Three.js 월드 좌표, 방 영역(필요 시 폴리곤), 가구·가전 위치, CLOiD 위치, 카메라, 목표 지점, 경로를 일관 좌표계로. 축 방향 차이 명시, 기준점·단위 확인, 위치→방 매핑, 로봇 위치와 대상 공간 혼동 금지.

## 11. 권장 아키텍처(책임 분리)
Twin Scene / Camera Controller / Semantic Zoom Controller / Agent Focus Controller / Agent Visualization / Rendering Pipeline / Minimap. 카메라 제어와 에이전트 판단 로직을 거대한 컴포넌트에 섞지 않음.

## 12. 성능
Draw call, frustum culling, LOD, 텍스처 압축, geometry·material 재사용, InstancedMesh, 불필요한 shadow update 제거, 비선택 공간 비용 조절, GPU 메모리, 로딩·해제, 카메라 이동 중 계산 최소화, React 렌더 루프와 재렌더 분리. 테스트 환경 명시 후 검증, 가능하면 60FPS. 품질 프리셋으로 단계적 조절.

## 13. UI
3D가 화면 중심, 주변 UI 최소. 필수: 전체 보기, 공간 집중, 물체 상세, 자동 추적 ON/OFF, 현재 에이전트 집중 공간, 현재 CLOiD 위치, 현재 목표·행동 상태, 미니맵, 그래픽 품질 설정. 긴 텍스트 패널이 가구·가전을 가리지 않게. 상세 판단은 필요할 때만 뜨는 오버레이·컨텍스트 패널.

## 14. 순서
P1 기존 구조 분석 → P2 고품질 Dollhouse(ortho, 자동 프레이밍, cutaway, 재질·모델, 조명·그림자) → P3 렌더링(HDR, PBR, GTAO, SMAA, 프리셋, 성능 측정) → P4 Semantic Zoom(선택, 자동 확대, 전환, 수준별 정보, 미니맵) → P5 Agent Focus(상태 연결, 집중 판정, 자동 전환, 수동 우선, 중복·충돌) → P6 Agent Visualization → P7 통합 검증. 실제 구현과 검증까지.

## 15. 완료 기준
시각: 집이 화면 대부분, 가구·가전이 기존보다 명확, 평면도 구조 유지, 재질·그림자 자연스러움, 확대해도 흐릿하거나 깨지지 않음.
카메라: 전체가 잘 들어옴, 공간·물체 선택 시 적절히 확대, 이동 자연스러움, 대상이 화면 밖으로 안 나감, 벽에 가림 최소화.
자동 집중: 집중 공간 변경 시 전환, 반복 이벤트에도 안 흔들림, 수동 탐색 시 자동 이동 중지, 자동 추적 재개 시 복귀, 계획 수정·종료 후 적절한 시점.
데이터: CLOiD 위치 정확, 공간·가전 ID 호환, 판단 결과와 트윈 데이터 연결, 시험 이벤트와 실제 이벤트 구분.
성능·안정성: 메모리·GPU 누수 없음, 리사이즈 대응, 프리셋 동작, 후처리로 색·UI 왜곡 없음, 기존 핵심 기능 정상.
에이전트 연동이 불완전하면 실제와 Mock을 명확히 구분하고 Mock으로 자동 집중·전환 검증.

## 16. 최종 보고
유지한 부분, 새로 구현·변경, 렌더링 파이프라인, 카메라·Semantic Zoom 구조, 자동 집중 동작, 실제 연동 여부, 테스트와 결과, 성능·제약, 못 한 것과 이유. 가능하면 기존 화면과 새 화면을 같은 시점에서 비교.
