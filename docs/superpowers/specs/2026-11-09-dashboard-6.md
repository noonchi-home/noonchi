# 대시보드 배치 (사용자 2026-11-08, 지금 판 = 6판)

## 사용자 말 (지금도 지키는 것만, 순서대로)

1. 대시보드 폰 칸 내용: 「여기에는 yolo와 fsm결과로 현재 어떤 액션을 도출하는지 표시 / 행동이나 관찰 대상의 상태나을 하기로 결정했을때 할일의 진행도는 트윈에서만 표시」
2. 설정 모달: 「마스코트를 누르면 설정 모달 나오게 하면 되겠네 다시 집 세팅하거나」
3. 판단 기록: 「PAM의 결과를 표시하니까 그게 결국 판단 기록 아니야?」
4. 실제 폰 말풍선: 「아니야 대시보드 폰칸이 아니라 실제 촬영중인 폰에」 (실제 폰 AR 화면의 말풍선은 그대로 둔다)
5. 마스코트: 「마스코트는 칸을 만들어서 있는게 아니라 배경이랑 같이 배치하고」, 「미어캣이 보면서 생각하는 것처럼 느껴질수 있자나」, 「마스코트 크기를 좀 줄이고 아랫부분이 완전히 밑에 선에 닿게 해줘」
6. 세로 폰·크게: 「그냥 폰화면은 세로로 하고 좌우로 배치할까 그러면 딱 맞을껐같은데 트윈화면도 크게하고」 + 질문에 고른 답: 실제 폰도 세로로 든다.
7. 6판(제안 2안 「다 겹쳐 놓기」를 고름: 영상·트윈이 화면 높이를 다 쓰고, 마스코트·말풍선은 그 위에 겹치고, FSM·행동은 영상 위 반투명 띠): 「2안으로 할건데 왼쪽이 트윈 오른쪽이 영상이야 마스코트(트윈과 영상 중간에 겹침)가 보는쪽은 영상 그리고 말풍선은 트윈 아래쪽에 이걸로 시안 빠르게 해봐」
8. 최신 판만: 「3판으로 바꾸면 그내용은 3판내용만있으면 좋겠어」 → 판이 바뀌면 지금 판 내용만 둔다.
9. 구조 확정: 사용자가 구조 그림(scratchpad/dashboard-proto/options/v6.html)을 보고 「좋아 이걸로 시안 만들어줘」. 그 그림의 자리·크기를 따른다(1920×1080 기준): 트윈 칸 1282×1048(왼쪽, 할 일 진행도는 트윈 왼쪽 위), 트윈 지도는 카드를 꽉 채움, 영상 590×1048(오른쪽, 세로 9:16), FSM·행동 띠는 영상 위쪽(약 96 높이), 마스코트 약 210×320을 경계에 겹쳐 세우고 아랫부분은 화면 밑 선, 말풍선 카드를 트윈 아래쪽(왼쪽 40부터 마스코트 앞까지)에 둔다. 마스코트가 영상 왼쪽 아래를 덜 가리도록 트윈 쪽으로 더 옮기는 것은 YOLO 상자를 가릴 때만 한다.

**6판만 보인다.** 이 지시가 작업 지시문의 다른 요청보다 우선한다. 비교 페이지(round8/index.html)에는 6판 캡처·잰 값·고른 것·남은 것만 둔다. 지난 판 캡처·지난 판과의 비교·before 폴더를 넣지 않는다. 저장소 문서·코드 주석·시험 이름에도 6판 결론만 쓰고 지난 판 언급을 남기지 않는다. 바뀐 내역은 변경이력.md에만.

## 배치 6판

```
+-------------------------------------------------------+------------------+
| 트윈 (크게, 화면 높이 꽉)                                  | 영상 (세로 9:16,  |
| 할 일 진행도는 여기에만                                     |  화면 높이 꽉)     |
|                                                       | + YOLO 상자·이름   |
|                                                       | FSM·행동 반투명 띠 |
|                                                       |                  |
|  ( 말풍선: 트윈 아래쪽 )  ◦ ◦  (머리)                       |                  |
|                              마스코트 → (트윈과 영상 사이에 겹침)            |
+-------------------------------------------------------+---------+--------+
                                  ↑ 마스코트 아랫부분이 화면 밑 선에 딱 닿는다
```

- 헤더 막대·맨 아래 줄·따로 된 마스코트 칸은 없다. 트윈과 영상 두 칸이 화면 높이를 다 쓴다.
- 왼쪽 트윈: 크게, 남는 너비를 다 쓴다. 행동을 하기로 정했을 때 할 일의 진행도(경로, 지금 단계, 몇 번째 단계인지)는 트윈에서만 보이고, 말풍선·마스코트에 가리지 않는 자리에 둔다. 확인한 기기 말풍선은 지금 규칙 그대로. 집 그림은 말풍선·마스코트에 방·기기·경로가 가리지 않게 놓는다.
- 오른쪽 영상(대시보드 폰 칸, 화면 이름 「폰 카메라」): 폰은 세로로 든다. 세로 영상(9:16, 표시 영상 720×1280)을 화면 높이에 맞춰 통째로 보이고(잘림 없음, contain), 그 위에 YOLO 결과(찾은 물건 상자와 이름·신뢰도)를 그린다. FSM 결과(PAM의 FSM 기억으로 본 지금 상태)와 도출한 행동(예: 대기, 컵 치우기)은 영상 위 반투명 띠로 얹는다. 띠 글은 마스코트에 가리지 않고, 띠는 YOLO 상자를 가리지 않는다(영상 아래쪽이 마스코트와 겹치면 띠는 위쪽에). 가로 영상이 오면 칸 안에 전체가 보이게 위아래를 비운다. 폰이 아직 붙지 않았으면 영상 자리에 연결 QR(칸에 맞춘 크기). 칸 크기는 폰 방향·데이터와 상관없이 바뀌지 않는다.
- 마스코트: 따로 칸(판·카드·LiquidGlass)이 없다. 트윈과 영상 사이 경계에 겹쳐 서고, 지금보다 작고, 보이는 아랫부분이 화면 밑 선에 빈틈 없이 딱 닿는다(밑 선에서 올라와 있는 모습). 그림(brand mascot.png)은 오른쪽(주둥이 쪽)을 바라보므로 대기 때는 영상을 본다. 행동하기로 정하면 좌우를 뒤집어 트윈을 본다(아래 「마스코트 방향」). 뒤집을 때 가슴의 LG 표시는 바로 읽히게 둔다. YOLO 상자·띠 글·트윈의 진행도와 기기 말풍선을 가리지 않는다.
- 마스코트는 누를 수 있다: 설정 모달(21st.dev Dialog, 저장소의 id 366 originui/dialog)이 DialogTrigger로 뜨고, 닫으면 초점이 마스코트로 돌아온다. 판이 없어도 마우스 올림·초점 링이 보이고 키보드로도 열린다.
- 말풍선: 트윈 아래쪽, 마스코트 왼쪽에 카드 하나로 둔다(꼬리 없음, 아래 「말풍선은 카드 하나」).
  - 말: 지금 하는 일을 쉬운 말로. 실제 대시보드에서는 실제 폰 말풍선과 같은 자료(지금 계획의 판단 글, 없으면 마지막 판단의 관찰, 폰 서버의 마스코트 줄)를 쓴다. 시안에서는 단계별 시나리오 말을 쓴다. 화면 글 규칙(생각 과정·설명 글 없음, npm run lint)을 지킨다.
  - 말풍선 카드 글만 가운데 정렬, 16px, 굵게(사용자: 「말풍선 안에 글씨만 가운데 정렬 + 좀 더 크게 + 굵은글씨 가자」, 2026-11-09; 글 크기 검사 허용 목록에 이 한 줄만 있음). 카드 크기는 그 글 두 줄에 맞춰 고정이고, 말 길이가 바뀌어도 아무것도 움직이거나 커지지 않는다(넘치면 자름). 말이 바뀔 때 움직임은 opacity·transform만.
- 판단 기록은 대시보드 폰 칸의 PAM 결과(YOLO·FSM으로 도출한 지금 행동)가 맡는다. 따로 판단 기록 목록을 두지 않는다. 지난 판단과 자세한 값은 DB와 API에 남는다.
- 설정 모달 안: 연결 상태, 시험 모드·실제 제어 상태, 허브, 에이전트, 지금 집 이름, 「집 다시 설정하기」(설정 화면으로 감), 폰 연결 QR. 입력창 없음(input·textarea·select·form·contenteditable 없음). Esc·바깥 누르기·닫기 단추로 닫힌다.
- 이름: 대시보드 영상 칸은 화면 이름 「폰 카메라」, 글에서는 「대시보드 폰 칸」. 촬영 중인 폰은 「실제 폰」. 맨 「폰 화면」은 쓰지 않는다(ui/tests/proto/wording.test.ts).
- 1920×1080·1440×900에서 잰 값(트윈 칸·집 크기, 영상 칸, 1단계 컵 상자, 마스코트 크기·자리, 말풍선 자리)을 적는다.

## 실제 폰 (ui/src/phone, feat/noonchi)

- 세로가 기본이다. AR 화면의 모든 상태(상태 줄, 위 줄, 엄지 자리, 큰 단추, 메뉴, 초점 이름표)를 세로로 맞춘다. 390×844, 412×915, 360×780에서 화면 밖으로 나가는 것 없이, 조준점이 가리지 않고, 단추가 엄지에 닿는다.
- 「가로로 돌려 주세요」 알림과 그 시험·사진은 지운다. 가로로 들어도 AR·추적·보내기는 그대로 되고(가로 배치는 남겨 두되 알림 없음), 화면 방향 고정·전체 화면은 요청하지 않는다(같이 요청하면 DOM 오버레이 AR이 안 떴다, ui/src/phone/core/ar.js 주석).
- 마스코트 말풍선(마스코트 얼굴+지금 하는 일)은 그대로 두고 세로 화면 위 줄에 맞춘다. 조준점·초점 고리·큰 단추를 가리지 않고, 같은 말을 두 번 보이지 않는다.
- 처음 화면은 폰을 세로로 드는 데 맞추고, AR 시작 단추가 스크롤 없이 보인다.
- 추적은 폰 위치와 카메라가 보는 방향(-Z)만 쓰므로 가로·세로가 같다. 기준점 맞춤·포즈·프레임 코드는 바꾸지 않는다.

## 그대로 지키는 것

- 21st.dev 부품만, 화면 코드는 배치만, 토큰 색만(npm run lint).
- 트윈은 카드를 꽉 채운다(사용자: 「트윈화면이 그냥 꽉채워도 될거같아 카드를」). 말풍선·마스코트는 지도 위에 얹고, 그 단계에 중요한 것(경로, 클로이드 표시, 확인한 기기 말풍선, 지금 방 이름)만 그 밑에 깔리지 않게 한다.
- FSM 상태·행동은 대시보드 폰 칸 영상 안에 떠 있는 카드다: 영상 끝에서 띄우고, 지금보다 더 투명해서 영상이 비쳐 보이고, 글은 어느 장면에서도 읽힌다. YOLO 상자·이름표를 가리지 않고 마스코트 밑에 깔리지 않는다. 사용자: 「그리고 FSM 상태랑 행동은 폰화면 내부에서 조금더 투명하게 떠있으면 좋겠어」.
- 마스코트 방향(사용자: 「대시보드 시안 팁을 주자면 두 카드가 서로 가까운선에 미어캣 을 배치 해서 대기할때는 카메라쪽을 보고 있다가 행동하기로 결정하면 좌우반전해서 왼쪽 보고 하는 구조도 좋을거 같아」): 마스코트는 트윈 카드와 영상 카드가 맞닿는 선 위에 선다. 할 일이 없을 때(대기·관찰)는 오른쪽 영상 쪽을 보고, 행동하기로 정하면(계획 진행 중) 좌우를 뒤집어 왼쪽 트윈 쪽을 본다. 뒤집기는 transform만 쓴다. 뒤집어도 가슴의 LG 표시는 바로 읽혀야 한다(표시 부분만 뒤집지 않고 다시 그리는 식).
- 두 카드는 맞닿는다(사용자: 「그래서 이건 너가선택해 트윈 / 카메라 카드 를 가까운 선끼리 딲맞게 해서 좌우반전이 더 진짜 같게 하던지해」 → 고름): 트윈 카드와 영상 카드 사이 틈을 없애 한 판처럼 붙이고, 가운데에 얇은 나눔선 하나만 둔다. 바깥 모서리만 둥글고 맞닿는 쪽 모서리는 각지다. 마스코트의 가운데 축을 그 나눔선 위에 두고, 뒤집을 때도 그 축을 중심으로 뒤집어(자리가 튀지 않게) 고개를 돌리는 것처럼 보이게 한다. 영상은 9:16을 그대로 지키고, 트윈이 남는 너비를 쓴다.
- 말풍선은 카드 하나다(사용자: 「말풍선은 그럼 그냥 카드하나로 표현하면 되겠지」). 꼬리나 생각 동그라미 없이 트윈 아래쪽에 카드 하나로 둔다. 크기는 부품 원래 글 두 줄에 맞춰 고정.
- 말풍선 카드의 말은 클로이드가 판단한 것과 실제 폰에 낸 명령을 쓴다(예: 「식탁 컵을 치우기로 했어요」, 「컵을 들라고 했어요」). 클로이드가 몸으로 직접 하는 것처럼 쓰지 않는다(「집어 들게요」 아님). 실제 폰 사람이 에이전트의 손이다.
- 시나리오는 0단계 「지켜보기」(계획·진행도 없음, 행동 대기, 마스코트는 영상을 봄, 카드 「식탁을 보고 있어요.」)로 시작하고, 1단계에서 행동을 정하면 마스코트가 트윈 쪽으로 돈다. 트윈 진행도 글은 계획 단계 이름만(식탁 확인 · 식탁으로 이동 · 컵 들기 · 싱크대로 이동 · 싱크대에 넣기 · 폰으로 알리기).
- YOLO 상자 모서리가 마스코트에 가리는 것(3단계 식탁 상자)은 그대로 둔다(사용자: 「그대로 둘거고」). 이름표는 가리지 않는다.
- 화면 글은 21st.dev 부품의 원래 글 크기(디자인 적용 전)로 쓴다. 멀리서 읽게 키운 크기(far 32px 같은 것)를 쓰지 않는다. 사용자: 「글씨는 또 왜이렇게 큰거야 ui 카드구조를 망가뜨릴정도로 크잖아」(트윈 말풍선 때 한 번, 이번이 두 번째), 「확인 바꿈 이런것도 글씨 왤캐 크냐」. 트윈 기기 말풍선(이름, 확인·바꿈 칩, 상태 줄)까지 모든 글이 해당된다. 넓은 화면(1920)이라고 키우지 않는다.
- 트윈 말풍선은 디자인 적용 전 크기, 확인한 기기에만, 점선 없음, pointer-events-none.
- 대시보드 입력창 없음.
- 화면 글 규칙(생각 과정·설명 글 없음).
- 「진행 중」 반짝임은 꺼 둔 채.
- 움직이는 것은 transform·opacity만, 캔버스·영상 크기를 움직이는 동안 바꾸지 않는다. 단계가 바뀔 때 끊김이 없는지 잰다(ui/scripts/measure-switch.mjs --mode visible, 90초, 가장 긴 간격 50 ms 이하).
